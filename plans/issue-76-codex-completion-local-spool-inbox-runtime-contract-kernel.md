## 注記 / 前提

- `RC-001`〜`RC-003` は triage の stable ID をrenameしていない。
- full-coverage escalation は不要と判断した。3 contract は callback→provider→filesystem と installer/configuration binding のboundedな直線 chainであり、implementation contractがreplay、collision、atomic publish、rollbackを具体化済みである。participant / boundaryの表現に詳細sequence diagram、外部protocol、cross-slice shared architectureは不要で、kernel表から因果関係を追跡できる。
- `NotImplementedOrMismatch`: `scripts/codex-notification-runtime/local-spool-provider.cs` と `scripts/codex-notification-runtime/spool-item-v1.schema.json` は required production address だが現時点では存在しない。近傍の `windows-app-notification-provider.cs`、fake provider、runtime `state/*.delivered` を代替にしない。
- `NotImplementedOrMismatch`: 現行runtimeはprovider loopと `chained_notify` deliveryを持ち、現行installerはWindows App Notification providerをpublish/configureする。exactly-one Local Spool provider gate、legacy provider非production化、new provider/schemaのinstall/APM mirrorは未実装である。
- `NotImplementedOrMismatch`: production interface / implementation / installed wiring / post-wiring filesystem resultは未検証である。本artifactは `Bound` を新規判断せず、`verification-kernel.agent.md` へ引き継ぐ。
- `OutOfScopeForThisPass`: consumer / Inbox / claim / ack / retention / cleanup / archive / recovery / toast / forwarding。RC-002のtemp best-effort削除を超えるlifecycle policyは追加しない。
- `ManualOnly`: 通常editorでresolved production Spool folderと各JSONを読めること、およびreal installed callback entrypointからfinal fileが生成されることは、downstream test design / verificationで実環境観測を分類する。
