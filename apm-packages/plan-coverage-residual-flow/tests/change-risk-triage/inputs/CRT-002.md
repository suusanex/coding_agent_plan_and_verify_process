# CRT-002 Change Facts

An installer process sends a publish request to a local broker process. The broker validates the message, stages one versioned record, atomically replaces the current durable record, and acknowledges the request. If acknowledgement is lost, the installer can retry the same request identifier; the broker replays the recorded outcome instead of publishing twice. Concurrent requests for the same identifier are serialized by the same broker-owned publication transaction.

Rollback uses the same request and publication lifecycle to restore the prior version. Production and fake transports have different registrations, but both enter the same broker handler and are checked against the same publication oracle. The change updates that bounded path, its installer wiring, and its end-to-end verification together. There is no separately owned consumer protocol or independent release unit.
