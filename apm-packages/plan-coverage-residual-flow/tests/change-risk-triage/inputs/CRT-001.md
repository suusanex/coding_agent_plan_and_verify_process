# CRT-001 Change Facts

A desktop process calls one operating-system API through an in-process native interop wrapper. The completion callback is marshalled onto the application's UI thread. The same application component is the only writer of the operation record in one durable local store. A separately launched status process later opens that store read-only during startup and displays the completed operation.

The implementation change replaces a production stub in the existing entrypoint, preserves the current operation identifier and record schema, and adds one end-to-end check from the platform call through the later reader. No independently deployed service, background worker, or replay queue is introduced.
