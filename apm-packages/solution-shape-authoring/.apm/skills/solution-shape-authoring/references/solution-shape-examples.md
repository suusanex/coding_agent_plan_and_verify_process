# Solution Shape 表現例

以下の見出し、表、箇条書きは読みやすさのための例であり、下流の必須フォーマットではない。案件の大きさに合わせて短縮または組み替えてよい。

## 例 1: 複数の実現主体・共有部分を持つ構成（共通 Bot 基盤）

`suusanex/grok_bot_core_observe_and_improve#23` を材料とした軽量スケッチの例。

### 構成・責務配置

論理責務ごとに独立サービスや別 LLM セッションを作らず、実際の実現主体を次の 5 つに分ける。

| 実現主体 | 担う論理責務 | 主な関係 |
| --- | --- | --- |
| Grok Bot（ホスト / 対話 UI） | ユーザー対話の受付・送信、Grok Bot 固有連携 | 入力を共通実行ホストへ渡し、送信結果と成否を返す |
| 共通サイクル実行ホスト（単一 CLI） | 一巡の進行制御、必要範囲の抽出、機械的差分保存、Git 同期・公開 | Bot 設定に応じて AI 呼出し有無を判定し、保存と Git 更新を実行 |
| 外部 AI CLI（必要時のみ起動する単一主体） | 意味判断、質問・推薦判断、更新すべき意味差分の生成 | 実行ホストから必要な文脈だけを受け取り、差分を返す |
| Git 作業ツリー / リモート main | 共有関心、Bot 個別記憶、根拠原文、操作履歴の保存先 | 共通ホストが読取り・差分書込み・同期・通常 push を担当 |
| Notion（ゲーム Bot 固有連携） | 非同期質問と部分回答の入力・表示画面 | ゲーム Bot 経路からだけ参照・更新し、全体記憶の正本にはしない |

### 機能配置

| 機能 | 担当・実現方式 | 重要な制約・境界 |
| --- | --- | --- |
| 一巡の進行と Bot 切替 | 共通ホストが Bot 定義（利用情報源・操作・推論要否）を見て制御 | 第 4 の Bot 追加時に、既存 3 Bot 固有の記憶形式や Notion 連携、固定段階（request/absorb 等）を強制しない |
| 意味判断と推論 | 判断が必要な場面だけ共通ホストが外部 AI CLI を 1 回呼出す | 感想のみの受付では検索・外部 AI 呼出し・全文再生成を行わない |
| 記憶・状態更新 | AI は意味差分だけを返し、共通ホストが対象箇所のみ機械保存する | AI 出力の全文上書きを避け、既存の有用な記憶・原文・操作実成否を保つ |
| 並行更新の Git 公開 | 共通ホストが fetch・条件付き rebase・通常 push を試行する | 強制削除や force push を前提にせず、意味的競合時は変更を保全して停止。再同期時に AI 再判断や外部送信を再実行しない |

### 代表的な実行経路

1. **感想のみの受付経路（ニュース・X 推薦 Bot）**
   - `Grok Bot UI` が感想を受領 → `共通ホスト` が推論不要と判定し外部 AI CLI を呼ばずに該当フィードバック差分だけを `Git 作業ツリー` へ機械保存 → 同期・通常 push して完了（AI 呼出し 0 回、他領域の全文再生成なし）。
2. **判断を伴う通常一巡と先行 push 競合時の経路（共通経路）**
   - `共通ホスト` が対象 Bot の状態と共有関心（必要範囲）を読込み → `外部 AI CLI` を 1 回呼び出し判断結果・必要操作・意味差分を取得 → `共通ホスト` が固有連携（例: ゲーム Bot の Notion 更新や送信）の結果を確認し記憶差分を機械保存 → リモート `main` 先行時は、AI 再推論・外部操作を再実行せず Git 再同期と通常 push だけを試み、解決不能なら未公開変更を保全したまま停止・報告する。

### 重要な違いがある代案（必要な場合のみ）

- **記憶更新の実現方式**: AI が記憶ファイル全文を書き換えて返す案 vs AI は意味差分だけを返し共通ホストが機械保存する案。
  - 後者は無関係領域の全文再生成・意図しない上書きを防ぎ、感想受付のような無推論保存経路をそのまま扱える。

## 例 2: 少量の入力を一度処理して終わる小さなツール

1 件の設定値またはレコード差分をローカルファイルへ保存する小規模 CLI の例。この程度の案件では数行で十分であり、複雑な図や比較表は書かない。

- **構成・責務配置**: `単一 CLI プロセス`（引数解析・1 件更新・原子的書き出し）と `対象データファイル 1 つ`（ローカル保存先）のみ。常駐プロセス、外部 AI、別管理台帳は置かない。
- **機能配置**: 指定キー 1 件の値だけをメモリ上で更新し、一時ファイル書き出しと置換で保存する。他レコードの内容はそのまま維持し、全件再生成、追加照合、独自バックアップ履歴は持たない。
- **代表的な実行経路**: CLI 引数（キー・値・ファイルパス）を受け取る → 対象ファイルを 1 回読込む → 該当 1 件だけを更新 → 一時ファイル経由で 1 回書き出して終了。
