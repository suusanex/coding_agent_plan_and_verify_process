## Known Evidence

- `RetryPolicy` stores only the immutable configured fallback and currently has no server-value input.
- `RetryingClient` is the sole production caller and directly forwards cancellation to `Task.Delay`.
- The repository contains no visible DI registration, factory, startup, HTTP response/header model, project, solution, or test runner configuration.
- A local .NET 11 probe showed `TimeSpan.TryParse("-00:00:01")` and `TimeSpan.TryParse("00:01:00")` succeed, while `"1.5"` fails in the current culture. Its accepted language is duration syntax and is not the required non-negative integer delta-seconds grammar.

## Known Assumptions

- “Retry-After delta” means a delta-seconds value rather than the HTTP-date form; the Plan does not request date parsing.
- The repository is a deliberately minimal smoke fixture, so validation may be limited unless the Adaptive flow identifies an available external harness.
