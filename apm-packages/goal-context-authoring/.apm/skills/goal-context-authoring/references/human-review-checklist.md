# Goal Context の任意レビュー

完成文の人手レビューは、ユーザーや適用中のプロセスが求めない限り任意。この確認を使っても、承認記録や新しい状態は必要ない。

**先に中心目的を読む。**

- 元の問いと最後の明示的な訂正を読み、Goal Context と比べる。誰のどの活動が対象で、何に困り、何を判断・実行できるようになるかは同じか。各文に根拠があっても、全体では情報の集約や機能の提供が目的にすり替わっていないか。
- 挙がった機能がすべて動いても元の負担が残る例を、Goal Context だけで未達と判定できるか。未採用の方式を別案に替えても、達成したい利用者の状態は変わらないか。
- ユーザーが目的案を訂正した場合、その意味が全文にも残っているか。確定した方式に合わせて目的を狭めたり、逆に目的に合わせて決定を弱めたりしていないか。

**その目的に照らして利用場面・決定・境界を読む。**

- 代表場面で誰が何をしたくてどんな結果を得るのかが読み取れるか。合意済みの結果や判定に必要な条件は Goal Context に、採用済みのシステム能力・方式は Decision Context に残っているか。
- 改修では影響される既存目的・利用場面が根拠と適用範囲付きで継承され、維持／追加／変更／廃止／未確認と承認権限を区別できるか。参照不能を「維持条件なし」にしていないか。
- 同じPRで継続文書の更新要否を判定し、必要な反映と整合確認を完了条件にしたか。変更なしでは理由付き更新不要とでき、新規開発や内部変更に無意味な文書を強制していないか。
- 原資料から出力を確認したとき、決定済みの詳細、条件、例外が、文書の形や簡潔さを理由に省略されていないか。
- 出力から原資料を確認したとき、目的、結果、理由、前提を含む各記述の意味、決定状態、適用範囲に裏付けがあるか。記録されていない理由を補っていないか。
- 明示的な先送りは現在の対象外という決定として扱い、採否不明の提案は決定扱いしていないか。目的と決定が矛盾するなら判断を求め、原資料にない設計上の疑問を追加していないか。
- Does the text avoid turning implementation details or general best practices into unstated product requirements?
- Did the author avoid inferring a capability from usefulness or promoting a proposal, assumption, or user silence into a settled decision?
- Are secrets, credentials, authentication material, and unnecessary personal data absent?
- Is every added heading or label useful to this document rather than copied from a template mechanically?
- 各決定の条件と例外がその決定の近くに置かれ、必須、推奨、暫定などの強さが原資料どおりに保たれているか。

The author may revise the text in any format. Do not add approval fields merely to record that this checklist was used.
